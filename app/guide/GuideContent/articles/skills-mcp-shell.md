## Три способа дать агенту возможность действовать {#overview}

В GrantTap рядом встречаются MCP, Skills и Shell. Они помогают агенту работать, но означают разные вещи. Понимание этой разницы особенно полезно, когда инструмент виден на телефоне, а ожидаемого вызова в истории нет.

**MCP server** предоставляет coding app инструменты через Model Context Protocol: например, поиск по документации или работу с конкретным сервисом. Его настройка, авторизация и доступность принадлежат компьютеру и соответствующему провайдеру.

**Skill** содержит инструкции и связанные материалы для определённой работы. Это может быть руководство по оформлению документации, чтению проекта или проверке дизайна. Skill не является дочерним агентом и не означает, что отдельный процесс уже запущен.

**Shell / CLI** — команды в окружении агента: `git`, `npm`, тестовый runner и другие программы. У одной shell-команды могут быть совершенно разные последствия, поэтому GrantTap различает обычный вызов, публикацию, сетевое действие и другие распознаваемые категории.

Начальную установку смотрите в [подключении MCP](/guide/installation), правила для этих возможностей — в [Governance](/guide/governance).

## Видно, разрешено, выбрано, использовано {#four-states}

Не сводите состояние инструмента к единственной галочке. У него есть несколько независимых ступеней.

| Состояние | Подтверждённый смысл | Чего оно не доказывает |
| --- | --- | --- |
| Configured / installed | Компьютер обнаружил настройку или локальный пакет | Успешный вход, initialization и реальный вызов |
| Available / allowed | Инструмент опубликован в каталоге соответствующего execution и не отмечен запрещённым | Что агент выбрал его для ответа |
| Selected / requested | Человек указал инструмент для отправки | Что провайдер действительно вызвал инструмент |
| Recorded use | Получено наблюдение вызова для соответствующего провайдера и execution | Что результат вызова независимо проверен как изменение файла |

Например, в GrantTap Lab выбран skill для README. Это означает просьбу использовать его при работе. Если агент ответил без подтверждённого вызова, интерфейс не должен приписывать skill выполненную работу. Аналогично установленный MCP не обязан иметь счётчик использования больше нуля.

:::tip Как проверить использование
Откройте детальную карточку возможности и её историю вызовов. Сверьте компьютер, провайдера и Task. Общий счётчик одноимённого сервера из другого чата не подтверждает использование здесь.
:::

## Где искать каталог {#catalog}

В проекте раздел инструментов и Skills показывает опубликованные компьютерами возможности. В чате браузер возможностей позволяет посмотреть карточку и затем явно выбрать подходящий элемент для сообщения. Строку можно открыть для изучения даже тогда, когда выбрать инструмент нельзя.

В карточке могут быть описание, native metadata, версия, авторизация, состояние конфигурации и подтверждённые вызовы. Недостающие сведения остаются не сообщёнными. Значок и описание помогают узнать инструмент; они не являются ни разрешением, ни инструкцией, которой приложение должно довериться.

У совпадающих названий могут различаться реализация, настройки и доступ. Поэтому ориентируйтесь на контекст компьютера и провайдера, а не только на имя или иконку. Особенно это важно, если один MCP установлен у Claude Code и Codex или на двух Mac.

## Выбор в сообщении {#selection}

Для учебного сценария откройте чат GrantTap Lab, найдите действительно доступный инструмент и изучите его detail. После выбора отправьте короткое задание, например проверить локальный README и предложить улучшения. Не выбирайте незнакомый сервис только ради красивого скриншота.

Выбор путешествует вместе с разрешёнными параметрами сообщения, но компьютер повторно проверяет маршрут и текущую доступность. Если MCP больше не разрешён для Task или skill исчез из папки проекта, отправка может получить понятный отказ. Включение запрещённого инструмента не происходит через простое открытие карточки.

Каталог одного компьютера также не устанавливает пакет на другом. При [передаче Task](/guide/handoff) проверьте возможности destination: там отдельно нужны provider configuration, подходящие права и initialization. Список желаемых возможностей проекта не заменяет их фактическую установку.

## Настройка отдельных инструментов {#named-rules}

В [Governance → Custom](/guide/governance#effects) можно дать named capability собственное решение. Например, разрешить один знакомый MCP server, а для остальных оставить Ask. Правило проекта не отменит глобальный запрет провайдера.

Для Shell именем может стать распознанная команда: `git` или `rm`. Для Deploy — фраза вроде `git push` или `npm publish`. Network отдельно распознаёт такие программы, как `curl` и `ssh`. Для scripts и Skills могут передаваться ограниченные fingerprints и content hashes, если исходный файл доступен для чтения.

Это описание механизма, а не обещание полного анализа произвольно запутанной shell-программы. Проверяйте фактическое **Enforcement** категории. Из наблюдаемого имени инструмента нельзя вывести защиту от любого обходного способа выполнить то же действие.

## Использование и ресурсы {#usage}

[Usage и отчёты](/guide/usage-reports) объединяют записи вызовов и доступные execution totals. Подробные строки и сохранённые агрегаты имеют разные пределы хранения: исчезновение старой подробности не должно обнулять уже сообщённый итог.

Duration, CPU и memory присутствуют только там, где есть соответствующие сведения. Некоторые значения измерены, некоторые сопоставлены с процессами за время вызова или оценены. Skill, связанный по времени с процессом, не получает автоматически доказанную точную долю всех его ресурсов.

Если вызовы не подтверждены, правильный ответ — Unknown или отсутствие сообщённых данных. Это не «инструмент никогда не использовался» и не «использовал ноль памяти». Выбранная возможность и выданное разрешение сами по себе не превращаются в usage.

## Если инструмент не работает {#troubleshooting}

Проверьте по порядку: выбранный компьютер online, provider установлен и авторизован, MCP опубликован в его каталоге, Governance разрешает действие, native sandbox подходит задаче. Затем смотрите exact refusal или [статус доставки](/guide/message-delivery) исходного сообщения.

Не лечите проблему удалением pairing, расширением глобального policy или повторной отправкой уже принятого запроса. Обновление helper и установка дополнительного MCP — разные действия. Подробности: [провайдеры](/guide/providers) · [обновления](/guide/updates) · [диагностика](/guide/troubleshooting).
