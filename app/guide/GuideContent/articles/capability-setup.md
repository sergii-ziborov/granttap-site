## Что настраивается в coding app, а что в GrantTap {#boundaries}

Чтобы агент использовал инструмент, недостаточно увидеть его красивую карточку на телефоне. Сначала возможность должна существовать в окружении нужного провайдера и компьютера, затем пройти авторизацию и правила, и только после этого — быть действительно вызвана.

**Coding app** владеет native конфигурацией MCP, загрузкой Skills и доступом к своим инструментам. **GrantTap** обнаруживает поддерживаемые сведения, показывает их в контексте Task и позволяет задать Project Governance. Каталог GrantTap не является универсальным installer, который одним нажатием переносит любое расширение на все компьютеры.

Для начала настройте сам GrantTap по [инструкции установки](/guide/installation), затем создайте безопасную [учебную Task](/guide/new-task). Ниже описана настройка ваших существующих возможностей; выполнять сторонние логины или устанавливать неизвестный MCP ради примера не требуется.

## Шаг 1. Выберите конкретное окружение {#scope}

Откройте нужный чат и проверьте Project, computer, provider и execution. Один сервер с одинаковым названием может быть настроен только у Claude Code, но отсутствовать у Codex. Другой Mac также имеет собственную конфигурацию.

В Devices посмотрите доступность компьютера и готовность интеграции. Для локального Mac отдельно проверьте [local access](/guide/mac-app#access). Новая запись в Account Mesh ещё не означает, что с этого endpoint уже пришёл свежий каталог.

Если вы собираетесь передать работу другому исполнителю, повторите проверку для destination. [Handoff](/guide/handoff) сохраняет Task, но не устанавливает автоматически все MCP и Skills source-компьютера.

## Шаг 2. Проверить уже установленный MCP {#mcp}

Сначала откройте native список MCP в самой coding app. Для Claude Code это предусмотренный `/mcp`, для Grok Build — `/mcps`; у других клиентов используйте их поддерживаемый plugin/settings интерфейс. Убедитесь, что выбранный сервер действительно настроен и coding app сообщает подходящее состояние.

Если сервис требует аккаунт, авторизуйте его штатным способом самостоятельно. GrantTap pairing не подменяет credentials стороннего сервиса. Для самого GrantTap MCP используйте опубликованные [plugin instructions](/guide/installation#codex), а не добавление произвольных дублирующих endpoints.

Далее вернитесь в Task и откройте браузер возможностей рядом с composer либо Tools & Skills проекта. Найдите тот же server. Изучите описание, provider/computer, version и authentication metadata, если они сообщены. Неизвестный статус не становится успешной авторизацией от одного refresh.

Если MCP отсутствует в native coding app, устанавливать его следует по инструкции владельца сервиса через поддерживаемый механизм клиента. Эта глава не предлагает выдуманную команду `granttap install-mcp`: такого общего пользовательского пути здесь нет.

:::warning Особенность Cursor
Не чините каталог ручным добавлением GrantTap HTTP MCP на localhost в Customize → MCPs. Текущий plugin использует свой поддержанный транспорт, а старая дублирующая запись может вызывать Cloud fetch failed. Сначала прочитайте [границы Cursor](/guide/providers#cursor).
:::

## Шаг 3. Проверить Skills {#skills}

Skill — пакет инструкций и связанных материалов. Он может быть личным, проектным или поставляться plugin. Проверьте его наличие в самой coding app и папку проекта, в которой открыт разговор. Один и тот же skill name в другом workspace не доказывает доступ здесь.

GrantTap умеет обнаруживать поддерживаемые `SKILL.md` в известных personal/project locations. Но наблюдение файла не подтверждает, что любой провайдер уже загрузил его: native convention и возможности установленной версии остаются важны.

Для практики выберите **уже установленный** безвредный Skill, например по документации. Прочитайте его описание и входящие действия. Если такого Skill нет, пропустите упражнение: отсутствие расширения не является поломкой GrantTap. Установка нового пакета — отдельный осознанный шаг по инструкции вашей coding app, с проверкой источника и нужных разрешений.

Вернитесь к capability detail в GrantTap. Project scope, доступность и recorded calls изучаются отдельно. Выбор Skill для следующего сообщения не делает его использование подтверждённым и не выдаёт право обойти Deny.

## Шаг 4. Shell и программы компьютера {#shell}

Shell запускает команды в native окружении агента. Наличие shell tool не доказывает, что установлены `npm`, тестовый runner или любая другая программа. GrantTap не является менеджером всех пакетов компьютера.

Проверьте необходимые программы в своём обычном терминале либо через поддерживаемый безопасный сценарий coding app. Для диагностики самого helper достаточно `granttap status`. Не запускайте production deploy, удаление данных или новый provider login просто для проверки связи.

В Governance обычный shell command может отличаться от распознанных Deploy, Network и Scripts. Например, `git push` относится к отдельному решению о публикации, а не только к разрешённому общему `git`. Это помогает задавать точечные границы, но не является полным анализатором любых запутанных команд.

## Шаг 5. Разрешить именно то, что нужно {#policy}

Откройте правильный Project → Governance. Для категории выберите Inherit, Allow, Ask, Deny или Custom. Custom позволяет разрешить один знакомый MCP и оставить остальные на Ask. В учебном проекте можно разрешить чтение/правки локального README, а `git push` оставить Deny.

Названное правило уточняет default категории. Global/provider Deny и обязательные host restrictions остаются сильнее. Выбор инструмента в composer — отдельное намерение для сообщения, не изменение policy. [Allow all в чате](/guide/governance#precedence) также не расширяет native sandbox.

Несохранённый draft и отправленная policy — разные состояния. После Save дождитесь Applying и фактически сообщённой revision. Компьютер может отклонить устаревшую ревизию или сообщить недоступный Engine; сохранённый черновик не означает успешно применённые правила.

## Шаг 6. Прочитать Enforcement {#coverage}

Project Governance требует работающего [GrantTap Engine](/guide/engine) и поддержанного native hook. Проверяйте точное сочетание computer, provider и kind.

| Статус | Практический смысл |
| --- | --- |
| **Enforced** | Hook может остановить запрещённое действие до запуска |
| **Observed only** | Сведения о вызове видны, гарантированная предварительная блокировка недоступна |
| **Unsupported** | Для этой категории нет нужного provider hook |
| **Unknown** | Готовность ещё не подтверждена |

В Codex установка hook definition и native trust/enabled различаются. Проверяйте точные GrantTap hooks, а не включайте глобально все доступные hooks. Strict с Incomplete не следует воспринимать как полностью изолированную среду.

## Небольшой сквозной пример {#exercise}

В своей Task GrantTap Lab выберите знакомый установленный Skill или MCP и попросите объяснить README без записи. После отправки проверьте [delivery](/guide/message-delivery), затем историю конкретного инструмента. Запишите результат четырьмя отдельными фактами: установлен, разрешён, выбран, вызов подтверждён.

Отсутствие последней ступени не исправляется повторным включением Allow. Агент мог решить задачу иначе, столкнуться с отказом или ещё не начать ход. Для совместной работы и ресурсных ограничений продолжайте в [делегировании](/guide/delegation), [лимитах](/guide/limits) и [пошаговом walkthrough](/guide/walkthrough).
