## Что именно вы предоставляете другому человеку {#scopes}

GrantTap разделяет личную сеть устройств и совместный доступ к проекту. Это помогает подключить второй iPad к своим компьютерам, не превращая его автоматически в участника каждого рабочего проекта, или дать человеку один Project Mesh без доступа к остальным.

Перед приглашением ответьте на три вопроса: кому выдаётся доступ, к каким репозиториям и Project, с какого устройства. Названия помогают ориентироваться, но разрешения привязаны к идентичностям и подтверждённым device links.

| Сущность | Её задача |
| --- | --- |
| Personal Account / Account Mesh | Связать свои устройства и компьютеры через личный passkey account |
| Company account | Описать person-level grant к выбранным repository IDs или всем репозиториям владельца |
| Controller device link | Создать отдельное подключение телефона или планшета, которое можно отозвать независимо |
| Project Mesh membership | Определить конкретные проекты, роль и разрешённые действия этого устройства |

Термин Company account в этой части интерфейса не означает, что GrantTap вошёл в GitHub от имени компании. Он не меняет Git provider ACL и не выдаёт компьютеру company login.

## Как устроен доступ к репозиториям {#repository-grants}

Владелец управляет company accounts отдельно от Project membership. Для аккаунта выбираются конкретные repository IDs либо общий grant `all`. Один человек может использовать несколько устройств с разными наборами Project и независимо отзываемыми связями.

Полный snapshot Project может содержать несколько репозиториев. Поэтому перед пересылкой проверяется доступ ко всем repository IDs этого snapshot. Если в проекте появился новый репозиторий, прежний выбранный grant может перестать покрывать весь проект до обновления разрешений. Grant `all` включает и добавленные позже репозитории.

Связанный или вложенный Project сохраняет собственную область доступа. Включить родительский Mesh недостаточно, чтобы автоматически открыть любой связанный проект. Выбирайте нужные Project явно.

:::note Доступ в GrantTap и доступ к исходникам
Разрешение видеть Project на телефоне не заменяет GitHub/GitLab permissions, локальные filesystem rights и авторизацию coding provider. Получатель работает с source code только в пределах прав своего компьютера и аккаунтов.
:::

## Пригласить человека в учебный проект {#invite}

Для первого знакомства используйте **GrantTap Lab** с демонстрационными задачами и без секретов. Владелец открывает нужный Project и **Members / Computers**, затем создаёт или выбирает account получателя и проверяет repository grant.

Устройство можно связать с account ещё до подключения компьютера и без единого Project. Такое подключение сначала имеет нулевой набор Mesh grants. Затем в деталях устройства владелец выбирает Project, роль и отдельные права.

Приглашение непосредственно в Project создаёт одноразовый код на пятнадцать минут. Получатель открывает Projects → Join a Project и сканирует приглашение либо использует доступный ввод ссылки. Не публикуйте код в общем чате и не используйте фотографию действующего QR в документации.

Не перепутайте его с [QR подключения телефона](/guide/pairing): pairing связывает devices/computers, а Project invite определяет участие в конкретном проекте. У account device QR и прямого computer QR собственные сценарии и сроки действия; ориентируйтесь на подпись текущего экрана.

## Роль и четыре практических права {#roles}

Интерфейс предлагает Viewer, Member и Admin, а под выбранной ролью показывает ответы на важные вопросы. Перед отправкой приглашения прочитайте именно их.

| Право | Что проверять |
| --- | --- |
| Видеть чаты проекта | Может ли устройство получить соответствующие conversations |
| Писать в них | Может ли человек продолжать работу сообщениями |
| Публиковать в Project | Может ли отправлять Project-scoped действия и события |
| Редактировать Governance | Может ли менять правила проекта |

Не воспринимайте роль как разрешение «всё на компьютере». Действие дополнительно проходит собственный runtime, Governance и native ограничения. Даже Admin не получает через это grant произвольный доступ ко всему диску.

Хорошая первая проверка — пригласить viewer к GrantTap Lab, убедиться, что нужные данные видны, а недоступные действия не предлагаются или получают явный отказ. Для публикации руководства этот сценарий снимается на тестовых данных, без обращения к реальному рабочему проекту другого человека.

## Почему важен телефон владельца {#owner-hub}

В реализованном пути совместного доступа телефон владельца остаётся hub. Он проверяет repository grants, выбранные Project и права member до пересылки данных или действий на компьютер.

Это означает, что наличие приглашения не превращает relay в независимый сервер всех разрешений. Если сообщение участника не проходит, проверьте доступность владельца и компьютера, а затем ограничения. Ошибка должна вернуться участнику отдельно, с причиной; молчание не равно принятому действию.

Если участник добавляет собственный компьютер, Project key передаётся по уже доверенному pairing его телефона с этим компьютером. Только после подтверждённого подключения компьютер становится маршрутом выполнения Project. Имя машины не является авторизацией.

## Изменить или отозвать доступ {#revoke}

Откройте детали member/device. Изменение роли обновляет правила дальнейшей пересылки. Удаление или приостановка account/device link останавливает новые данные и действия через телефон владельца. Несколько устройств одного человека отзываются независимо.

Уже показанные и скачанные материалы нельзя «забрать обратно» с другого устройства. Поэтому перед приглашением проверяйте область доступа, а для секретов учитывайте [границы endpoint безопасности](/guide/security#endpoints).

Старые device invites без account могут отображаться как legacy. Назначение им account включает repository gate сразу; после такого изменения снова проверьте доступность нужных Project.
