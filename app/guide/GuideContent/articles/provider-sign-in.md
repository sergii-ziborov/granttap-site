Вход в GrantTap связывает ваши устройства. Вход в Claude, Codex, Grok или Cursor даёт выбранному компьютеру доступ к соответствующему провайдеру. Это разные учётные записи и разные полномочия. Успешный passkey GrantTap не авторизует CLI автоматически.

## Где начать {#start}

1. Откройте **Devices** и управление нужным компьютером.
2. В **Coding agents** найдите провайдера.
3. Проверьте состояние: Signed in, Sign-in required, Not installed или статус, который не удалось проверить.
4. Нажмите **Sign in** либо **Sign in again**.
5. Проверьте имя компьютера в открывшемся окне. Вход будет завершаться для него.

Если инструмента нет, сначала требуется его поддержанная установка. Кнопка входа не создаёт установленный CLI. Если компьютер недоступен или использует старый модуль без этой возможности, ошибка относится к маршруту управления, а не обязательно к паролю.

## Открыть страницу провайдера {#browser}

Нажмите **Open sign-in page** / кнопку открытия страницы. Проверьте домен и используйте собственный аккаунт провайдера. GrantTap показывает полученную от CLI ссылку и следит за результатом на компьютере. Нажатие на ссылку ещё не означает, что CLI получил авторизацию.

:::capture provider-grok-login

В сценарии с device code сравните код из приложения с кодом на странице провайдера. Учебный QA12-CODE на снимке не действует и не является ключом. Реальный короткий код действует ограниченное время; его нельзя публиковать в отчёте или пересылать постороннему человеку.

## Claude Code и ручной код {#claude}

Для поддержанного потока Claude Code окно может предложить защищённое поле **authorization code**. Завершите вход на странице провайдера, затем вставьте полученный код в это поле и отправьте. Поле существует для ответа именно этому процессу входа. Оно не предназначено для API key, passkey GrantTap или произвольного пароля.

:::capture provider-claude-login

Пока код не принят и компьютер не подтвердил результат, авторизация остаётся незавершённой. Если поле исчезло, прочитайте итоговое сообщение. Затем вернитесь в управление и проверьте состояние провайдера через Refresh status.

## Закрыть окно и продолжить {#resume}

Закрытие Done убирает окно. Если поток ещё активен, в карточке может появиться **Continue sign-in**. Откройте его, чтобы вернуться к текущему входу. Это предпочтительнее повторного запуска параллельной авторизации.

**Cancel sign-in** отменяет текущий процесс входа. Отмена не отзывает все ранее выданные провайдером сессии и не удаляет аккаунт GrantTap. Если код истёк, отмените старый поток, убедитесь в его завершении и запустите новый.

## Когда статус не подтверждён {#unknown}

Unknown означает, что модуль не получил достаточного подтверждения. Не считайте его автоматически Signed out. Причиной могут быть версия CLI, нестандартная установка, недоступность команды проверки или ошибка сети. Сначала прочитайте результат, проверьте инструмент на выбранном компьютере и обновите модуль при необходимости.

Запрос, уже завершившийся ошибкой авторизации, не следует считать автоматически исполненным после входа. Вернитесь к исходной отправке, обновите статус и проверьте историю перед осознанным повтором. См. [восстановление запроса](/guide/request-recovery).

## Истёкший вход Claude Code в терминале {#expired}

Вход консольного Claude Code может истечь, когда приложение Claude на том же Mac ещё вошло. Тогда сообщение с телефона не выполняется, а прежний модуль показывал сырую ошибку вида «Failed to authenticate … claude auth login». Начиная с MCP 0.8.161 такая ошибка приходит как **Sign-in required for Claude Code** с действием входа, а Devices больше не показывает этого провайдера как вошедшего, пока он отказывает в запусках. С MCP 0.8.165 компьютер сообщает и об отсутствии лимитов по этой причине.

1. Откройте **Devices** → нужный компьютер → **Claude Code** → **Sign in again**.
2. Либо выполните в терминале этого компьютера `claude auth login`.
3. Отправьте маленькое тестовое сообщение в ту же Task и проверьте, что агент ответил.

Приложение 268 распознаёт и формулировки старых модулей, но точный статус в Devices даёт только обновлённый MCP.

:::check Что считать успехом
Компьютер подтвердил завершение входа; карточка провайдера показывает актуальный результат проверки; маленький тестовый запрос выполняется в нужной Task. Отдельное окно браузера с сообщением об успехе не заменяет эти три проверки.
:::

## Точечный выход и восстановление {#scope}

Для отзыва доступа используйте настройки конкретного провайдера и конкретного устройства. Отвязка компьютера от GrantTap, удаление аккаунта GrantTap и выход из Claude/Codex — разные операции. Подробности — в [восстановлении доступа](/guide/account-recovery) и [безопасности](/guide/security).
